My models.py is the simpler of the two. It has about 160 lines and only the six models the assignment asks for, while the LLM’s robot-models.py runs about 600 lines. Each model in mine holds just a few plain fields: the schedule is a string like “MWF” with a start and end time, each lecture gets one fixed QR code, and an upload just stores the image and the decoded code. The LLM version is clearly more complete. It adds a QRToken model that rotates the displayed QR code every 30 seconds, so a photo forwarded to a friend quickly stops working. It also adds an AttendanceRecord table with one row per student per lecture, marked present, late, absent or excused, which makes attendance rates simple counts. Even so, mine is much easier to implement. It needs no image library (it uses FileField instead of ImageField) and no background jobs, and it has only one constraint to reason about. The LLM’s extra features only work if someone also builds the parts it leaves out of the file: a verification service that checks tokens and image hashes, and a job that creates absent records after each lecture. For this class project I would keep my own model because it covers the requirements and I understand every line of it. I would borrow two small ideas from the LLM version: using secrets instead of random to generate the QR code, since random is predictable and someone could guess codes, and adding a uniqueness constraint so a student can’t check into the same lecture twice.
